# 仙加味短影片全自動化流程

## 正式目標
以 30 秒、9:16 直式短影片為主要內容形式。好的既有文案可轉為短影片腳本使用，但不得把已發布內容只換句話重發。

## 自動化流程
1. 文案挑選：從品牌故事、角色、產品、生活情境與合格既有文案中選題。
2. 腳本重寫：改成自然口語與 30 秒小故事，不用廣告念稿式語氣。
3. 分鏡：至少 8 個明顯不同動作／鏡頭節點；場景、姿勢、鏡頭、表情需依內容自然變化。
4. 角色一致：固定仙加味 Q 版小老闆、小鹿、小烏龜；核心造型不可變形。
5. 童聲：自然 5～6 歲台灣小男孩感；逐句生成／處理；人工控制停頓；禁止成人底聲硬升調。
6. 嘴型：有口白的鏡頭必須 lipsync；停頓時嘴巴停止；眼神與頭部方向需配合說話內容。
7. 動畫生成優先順序：Runway → Higgsfield → HeyGen，可依當下可用額度與功能互相搭配。
8. 視覺後製：Canva 用於封面、品牌片尾、Logo、CTA、字卡與必要視覺素材；不得生成錯誤中文字或錯誤產品包裝。
9. 音訊後製：口白為主；可視情境加入低音量背景音樂與腳步、翻頁、杯子、雨聲等環境音。人聲出現時音樂自動壓低。
10. 字幕：繁體中文、大字、手機可讀；依實際口白時間對齊，不以標點符號機械停頓。
11. 品牌收尾：顯示「仙加味｜補養，是一種節奏。」
12. CTA：顯示「想了解更多，歡迎加入仙加味官方 LINE 詢問」，停留約 3.8～4 秒。
13. 自動檢查：角色、場景、動作、嘴型、字幕、音量、圖文、產品外觀、品牌字、法規、重複內容。
14. 版本保存：所有測試與待審核版本只更新 GitHub 暫存分支，不直接合併 main。
15. 待審核部署：用 Render 部署可直接用手機觀看的待審核頁。
16. 人工審核：使用者確認通過後，才可進入正式版整理與發布流程。
17. 正式發布：未經人工審核不得自行合併 main 或發布到社群。

## 工具自動切換規則
- Runway 可用時：優先做多場景動畫、鏡頭變化與角色動作。
- Higgsfield 可用時：優先利用固定角色 reference element 維持小老闆一致性。
- HeyGen 可用時：優先做自然童聲、嘴型同步與必要的配音／嘴型工作。
- Canva 可用時：處理正式片尾、封面、Logo、CTA、品牌字卡。
- GitHub：保存腳本、規格、版本與製作程式。
- Render：部署待審核版本。

## EP01「認識小老闆」硬規格
- 30 秒、9:16。
- 至少 8 個不重複鏡頭／動作。
- 動作包含走進場景、揮手、蹲下與夥伴互動、桌邊整理、拿杯、休息、起身、三角色收尾等自然變化。
- 不能把同一段短動畫放慢或重複填滿 30 秒。
- 有說話的段落嘴型必須同步。
- 聲音要比現有 V3 更像自然小朋友，不能有成人念稿感。
- 本集不放正式產品包裝，避免產品外觀風險。

## 自動化守門
任何一項不符合以下條件，直接保留在待修正狀態，不可送正式發布：
- 聲音像自然小朋友
- 嘴型同步
- 動作／場景不重複
- 小老闆、小鹿、小烏龜一致
- 無 AI 亂碼中文字
- 品牌與 CTA 正確
- 產品出現時外觀完全符合正式資料
- 不含違規療效宣稱
- 可正式上線
